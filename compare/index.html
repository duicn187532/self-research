研究工作台

把書架上七篇論文放在同一張表上：它們怎麼表示記憶、怎麼處理過期的資訊、各自驗證到哪裡，以及合起來還留下哪些問題。用來找研究題目與設計實驗，不用來排名。

怎麼讀這一頁

這一頁的每個判斷都出自各篇精讀頁（已對照全文的內容），點格子裡的連結可以回到出處。「未提及」不等於「不支援」：原文沒寫，只表示我們無法從原文確認。不同評測、不同回答模型、不同評分方式的分數不能互相排名。下面的缺口只在本站這七篇的範圍內成立，不代表整個領域沒有人做過，也不是新穎性的主張。

03

跨論文的研究問題

六個問題，每個都列出七篇怎麼處理、還缺什麼。標記的意思：已有解法 有方法且有對應實驗；部分 有方法，但證據只涵蓋部分條件；證據缺口 本站七篇中沒有可以回答它的實驗。

舊記憶什麼時候算失效？誰來判斷？

部分

七篇怎麼處理
七篇在不同時間點判斷：寫入時由 LLM 判斷（Zep、CUPMem）、持續衰減（FadeMem）、查詢時由代理判斷（APEX-MEM）、寫入時確定性標記並在回答時重算（StateMem），以及 ATMS 的「隨時、以標籤表示」（ATMS）。
還缺什麼
各自有解法，但沒有一個評測在同一條件下比較這幾種時間點。Zep 只在 STALE 受測，APEX-MEM 和 FadeMem 都沒有在 STALE 或 StateMemBench 上受測。

失效的記憶該刪除還是保留？

證據缺口

七篇怎麼處理
FadeMem 刪除以控制容量；Zep、APEX-MEM、CUPMem、StateMem 都保留。Always-On 綜述 要求刪除必須傳播到衍生記錄，並指出衰減不等於刪除。
還缺什麼
沒有論文在同一評測下比較刪除與保留對準確性、儲存與稽核的影響。FadeMem 在 LTI-Bench 有 17.9% 的關鍵事實沒有保留，原文沒有錯誤分析。

與新資訊語意不相似的舊記憶，要怎麼被找到？

部分

七篇怎麼處理
STALE／CUPMem 的 Type II 正是這種情況（腿斷了 → 騎車通勤）。Zep 與 FadeMem 都從語意相似的候選裡找衝突；CUPMem 加上常識推測的受影響領域；StateMem 與 ATMS 依靠明確記錄的依賴。
還缺什麼
CUPMem 在 STALE 上有提升，但 schema 與評測同源、沒有留出集；依賴從哪裡來（抽取品質）在七篇中都沒有單獨評估。

多個互斥的情境能不能並存？

證據缺口

七篇怎麼處理
ATMS 的核心就是同時維護多個一致的假設環境。Zep 的兩條時間軸與 APEX-MEM 的版本並存只涵蓋時間情境。
還缺什麼
本站的六篇 LLM 記憶論文都沒有評測假設情境（例如「如果我搬去台中，通勤怎麼辦」）；ATMS 有機制但沒有量測。

切換回先前的情境時，之前的推論能不能直接重用？

證據缺口

七篇怎麼處理
ATMS 把「切換情境就要重算」列為傳統 TMS 的限制之一，標籤讓推論在任何環境下都可以重用。StateMem 與 APEX-MEM 都在每次回答時重新推算。
還缺什麼
沒有任何一篇量測重用帶來的節省或正確性差異；ATMS 的效率主張本身也沒有量測（見 ATMS 研究者分析 C）。

準確性、容量、成本、可恢復性之間怎麼取捨？

部分

七篇怎麼處理
FadeMem 用 55% 儲存換到較高的保留率；APEX-MEM 的 token 大多花在代理迴圈；CUPMem 每筆成本約 LightMem 的 18 倍；StateMem 發現對話放得進 context 時，只改回答提示詞的包裝器勝過完整的 StateMem；Always-On 綜述 提出可證偽的「受控複利」準則。
還缺什麼
每篇各報一兩個維度，沒有共同的成本帳。可恢復性在七篇中只有 Always-On 的 AOEP 試點量過。

分成五類。每一條都附出處；這些是讀七篇原文後整理出的觀察，不保證本站以外的文獻沒有做過。拿來當研究題目之前，請先做文獻搜尋。
