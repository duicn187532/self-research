    01

    問題：沒說出口的「過期」

    論文的開場例子 原文 §1

    使用者先說：「我每天騎腳踏車上班，可以推薦一些裝備嗎？」幾個月後又說：「我昨天打籃球摔斷了腿，要怎麼恢復比較快？」第二句沒提到腳踏車，也沒有否定第一句，但之後使用者請助理規劃通勤時，助理不該再建議騎車。

    你記得好朋友每天騎腳踏車上學。後來他說他的腿受傷了，要打石膏。他沒有說「我不騎車了」，可是你應該自己想到：他這陣子沒辦法騎車。

    這篇論文在考 AI：朋友沒有明講的時候，它能不能自己想到「以前記得的事已經不對了」。

    作者把這種情況叫隱性衝突（implicit conflict）：新的發言讓舊記憶失效，但兩者在字面上沒有矛盾，要靠上下文推理和常識才看得出來。分兩種：

    • Type I 共指衝突：新舊發言講的是同一件事，只是值變了。例如先說住西雅圖，後來說在波特蘭辦水電。
    • Type II 傳播衝突：新發言改的是另一件事，影響連鎖傳到舊記憶。例如腿斷了（健康）→ 不能騎車通勤（通勤方式）。

    現有評測多半只考「能不能找回以前說過的話」，很少考「知不知道那句話已經不成立」。

    作者主張把對話記憶看成潛在狀態追蹤（latent state tracking），借用 HMM [34] 與 POMDP [18] 的觀點：使用者的狀態 \(S_t\) 不可直接觀測，每則訊息 \(m_t\) 只是部分、有雜訊的觀測。一般 RAG 依語意相似度取回記憶，偏好相似而非時間上有效，所以容易把「騎車通勤」的舊記憶取回來回答通勤問題（§1，引 [9]）。

    和知識衝突研究的差別（§2）：不是在互相競爭的事實中二選一，也不是補上缺少的事實，而是判斷新觀測是否改變了潛在狀態，進而讓早期記憶衍生的假設失效。

    原文要點 原文 Abstract

    STALE 有 400 個經專家驗證的衝突情境，每個情境用三個維度探測，共 1,200 個評測查詢，涵蓋 100 多個日常主題，上下文最長約 150K tokens。最好的模型整體準確率也只有 55.2%。模型常接受查詢裡夾帶的過時假設，也難以意識到使用者某方面的改變應該讓相關記憶失效。作者另外提出原型系統 CUPMem 作為初步基線。

    自我檢測
    Type I 和 Type II 的關鍵差別是什麼？

    Type I：新舊發言針對同一個屬性，值不相容。Type II：新發言更新的是另一個屬性，透過因果或邏輯依賴，讓舊的、不同屬性的信念失效。

    為什麼一般 RAG 會在這類問題上出錯？

    它依語意相似度取回記憶。問通勤時，「騎車通勤」的舊記憶和查詢最相似，而「腿斷了」那則和通勤字面上無關，不一定會被取回，或取回了也不被當成決定性證據。

    形式化：潛在狀態與兩條公理

    符號原文 §3.1
    \[ H = \{(m_t, r_t)\}, \qquad \mathcal{A} = \{a_1, \ldots, a_k\}, \qquad S_t = \{\, v_t(a) \mid a \in \mathcal{A} \,\} \]
    符號意思（原文 §3.1）
    \(U, G\)使用者、LLM 助理
    \(H\)依時間排序的互動紀錄；\(m_t\) 是使用者訊息，\(r_t\) 是助理回覆
    \(\mathcal{A}\)有限的使用者屬性集合，例如健康狀態、通勤方式、居住地；每個屬性 \(a\) 的值域是 \(V_a\)
    \(S_t\)時間 \(t\) 的潛在使用者狀態，所有屬性目前值的集合，不可直接觀測
    信念 \(v_t(a)\)由觀測 \(m_t\) 支持的屬性值，也就是助理根據對話對屬性 \(a\) 的最佳理解
    \(\mathcal{K}\)世界知識（常識）
    隱性衝突成立的充要條件原文 §3.2
    \[ \textbf{Axiom 1 (Belief Incompatibility):}\quad \exists\, o < n,\ a \in \mathcal{A}:\quad m_n \models_{\mathcal{K}} \neg v_o(a) \] \[ \textbf{Axiom 2 (Non-explicit Invalidation):}\quad \forall\, m_j \in \{m_{o+1}, \ldots, m_n\}:\ \neg\,\mathrm{ExplicitInv}\big(m_j, v_o(a)\big) \]

    要算是「偷偷過期」，要同時符合兩個條件。第一，新的話一想就知道跟舊的事情不能同時成立。第二，從頭到尾沒有人明講「以前那樣已經不是了」。

    公理 1（信念不相容）：在常識 \(\mathcal{K}\) 之下，新觀測 \(m_n\) 推得出舊信念 \(v_o(a)\) 不成立。可以是直接給出不相容的新值，也可以是改變了相關屬性、進而排除舊值。

    公理 2（非明示失效）：從 \(m_o\) 之後到 \(m_n\)（含）為止，沒有任何一句話明說舊信念失效。「明說」包括字面否定（「我不再……」）、直接更正（「其實我現在……」）、或明確標註過時。間接暗示不算。

    公理 2 同時保證兩件事：失效只能靠推理發現，而且衝突沒有在更早就被明白解決。

    \(\models_{\mathcal{K}}\) 讀作「在世界知識 \(\mathcal{K}\) 下蘊含」。這個定義把「常識推理」放進了蘊含關係，所以衝突是否成立本身依賴 \(\mathcal{K}\) 的邊界，例如「找到樹皮蠍＋乾熱」是否足以蘊含「不住波特蘭」 導讀補充。實務上，這個判斷交給 LLM 品管（§3.4 Step 3）與人工審查（附錄 D.3），審查也會以「只靠鬆散的邏輯聯想」為由拒絕樣本。

    \(\mathrm{ExplicitInv}\) 是表層語言的判斷，沒有形式定義；實際上由生成提示詞中「不得有明確語言否定、不得提及屬性名稱」等限制來保證（附錄 D.2）。

    自我檢測
    使用者說「我已經不騎車上班了，改搭捷運」，這算隱性衝突嗎？

    不算。這是明確的否定與更正，違反公理 2。

    公理 2 為什麼要涵蓋 \(m_n\) 本身？

    如果 \(m_n\) 自己就說了「我不再……」，衝突就變成明示的，不需要推理。

    03

    兩種隱性衝突

    Type I：共指衝突（co-referential）原文 §3.3
    \[ m_o \text{ supports } v_o(a),\quad m_n \text{ implies } v_n(a),\quad v_n(a) \models_{\mathcal{K}} \neg v_o(a),\quad m_n \text{ does not mention or negate } v_o(a) \]
    Type II：傳播衝突（propagated）原文 §3.3
    \[ \exists\, a, b \in \mathcal{A},\ a \neq b:\quad b \xrightarrow{\ \mathcal{K}\ } a,\qquad v_o(b) \to v_n(b) \ \text{constrains } v_n(a) \text{ to be incompatible with } v_o(a) \]
    原文 §3.3 的兩個例子
    類型舊觀測 \(m_o\)新觀測 \(m_n\)失效的信念
    Type I住在西雅圖在波特蘭的新公寓辦水電居住地（同一屬性）
    Type II已經習慣波特蘭的生活步調在靴子裡發現樹皮蠍，是被持續的乾熱逼進室內的居住地，由「氣候與當地害蟲」傳播而來

    第一種像是：你以前說最喜歡紅色，現在說最喜歡藍色。講的是同一件事，答案變了。

    第二種比較難：你以前說每天去公園溜狗，現在說你對狗毛過敏得很嚴重。你沒提到溜狗，但聽的人要自己想到：你大概不能再每天溜狗了。

    Type II 比較難，因為中間有一條沒說出來的依賴鏈：新資訊改了 A，常識告訴我們 A 會影響 B，所以舊的 B 不成立。模型要自己補出這條鏈。實驗也證實 Type II 幾乎全面比 Type I 低分（見 07）。

    符號提醒 導讀補充：§3.3 的形式定義把上游屬性記為 \(b\)、被失效的目標記為 \(a\)（\(b \to a\)）；但 §3.4 Step 2 和附錄的生成提示詞把上游記為 A、目標記為 B（A → B）。字母方向相反，讀的時候要對清楚。

    兩類被定義為「互斥」。實際分類由生成流程指定，人工審查若發現分錯類會標為 WRONG TYPE 並改標籤（附錄 D.3），但沒有報告改標的比例。

    干擾 session 的過濾規則 原文 附錄 D.2

    夾在 \(\text{Session}_o\) 與 \(\text{Session}_n\) 之間的干擾內容，不得與 \(m_o\) 矛盾或直接延伸它；\(\text{Session}_n\) 之後的干擾內容則同時對 \(m_o\)、\(m_n\) 做更嚴格的過濾，確保 \(m_n\) 是目標屬性唯一的衝突來源。過濾器把「矛盾」和「補充、延伸、直接接續」都視為不安全。

    出題老師先寫一句「以前的事」，再請一個專門搗蛋的小幫手寫一句「後來的事」，故意讓兩句話表面上看起來沒關係。然後把這兩句藏在一大堆不相干的聊天裡，看 AI 能不能找出來、想清楚。

    整個資料集是 LLM 生成＋人工審查。關鍵設計是「長草堆」：每筆有 50 個 session、約 593 輪對話、平均約 15 萬 tokens，真正有用的只有兩個 session。這同時考了長上下文檢索和衝突推理。

    人工審查的四種標記：ACCEPT（不需改，或只微調探測題）、WEAK REJECT（要改 \(m_o\) 或 \(m_n\)，改完重跑包裝與草堆）、WRONG TYPE（衝突成立但類型標錯，改標籤）、REJECT（只靠鬆散聯想、\(m_n\) 太弱、或失效說得太明白，直接移除）。

    可追問的地方 導讀補充：人工驗證只涵蓋兩個高分的閉源模型，沒有涵蓋記憶框架或 CUPMem 的輸出。CUPMem 的 PR 分數高達 75–78%，而評審對 PR 的判準是「識破陷阱或承認新狀態」；一個傾向先質疑前提的系統，即使後續建議不夠好也可能通過，這部分沒有被人工驗證。

    模型在看哪裡：注意力分析

    跨片段注意力分數與比值原文 附錄 E.4
    \[ s_\ell(X \to Y) = \frac{1}{|H|\,|X|} \sum_{h \in H} \sum_{i \in X} \sum_{j \in Y} A^{(\ell,h)}_{ij}, \qquad r_\ell = \frac{s_\ell(Q \to \text{Session}_n)}{s_\ell(Q \to \text{Session}_o)} \]
    符號意思（原文 附錄 E.4）
    \(A^{(\ell,h)}_{ij}\)第 \(\ell\) 層第 \(h\) 個 head，token \(i\) 對 token \(j\) 的 softmax 後注意力權重
    \(s_\ell(X \to Y)\)片段 \(X\) 的 token 平均分配給整個片段 \(Y\) 的注意力總量（對 head 再取平均）
    \(Q\)最後的查詢
    \(r_\ell\)查詢看新證據相對於看舊證據的比例；大於 1 代表更偏向新證據
    雜訊基線把證據 session 換成它在草堆中緊鄰的干擾 session，再算一次

    科學家偷看 AI 讀題時眼睛盯著哪裡。答對的時候，AI 比較常盯著「腿斷了」那段；答錯的時候，它一直盯著「愛騎車」那段。而且 AI 很少把這兩段放在一起想。

    分析對象是 Qwen3.5-9B 與 27B，只看 SR 與 IPA（PR 答對的太少，無法分組）。每個類型 × 對錯組合最多取 20 筆。三個發現：

    • 查詢 → 新／舊證據的注意力明顯高於雜訊基線，代表模型確實有找到相關證據。
    • 新證據 → 舊證據的注意力很弱，接近雜訊基線：模型很少在內部「對照」兩段 session。
    • IPA 答對的樣本，\(r_\ell\) 較高，尤其在中間層。Type II 的「查詢 → 新證據」與跨 session 注意力都比 Type I 弱，和 Type II 較難一致。

    作者自己強調這是診斷性而非因果性的分析：注意力不完全決定輸出，樣本也小（每組至多 20）（附錄 E.4 Limitations）。結論是「行為較可能由以查詢為條件的路由決定，而不是先做跨 session 調和」。

    延伸思考 導讀補充：在約 15 萬 tokens 的輸入上，把注意力「平均到整個片段」會被片段長度與位置影響；論文用相鄰 session 當雜訊基線控制了位置，但沒有控制兩個證據 session 的長度差異。

    自我檢測
    為什麼要用「相鄰的干擾 session」當基線？

    控制位置效應。若證據 session 的分數只是因為位置靠近查詢而偏高，相鄰 session 也會一樣高；高於基線的部分才算內容驅動。

    CUPMem 和 LightMem 的根本差別是什麼？

    批判性閱讀

    原文附錄 A 自述的限制：每筆只有一個衝突（沒有反覆更新、多屬性連動或漸進漂移）；資料由 LLM 生成，可能不像真實對話；干擾 session 來自其他資料集；LLM 評審可能漏判開放式的正確回答；長上下文檢索能力與衝突推理能力在分數中糾纏；CUPMem 依賴預先定義的 schema。以下是本頁的補充評論 導讀補充。

    優點

    • 問題定義清楚，兩條公理把「隱性」講得可操作；Type I／II 的區分抓到了相似度檢索的盲點。
    • 三個探測維度設計得好，能把「知道」「頂住誤導」「用上」分開量。PR 的近零結果是很有價值的發現。
    • 透明度高：所有生成、評分提示詞都公開，資料與程式碼釋出，評審的人工一致性有細到各維度的 FPR／FNR。
    • LightMem 診斷把失敗定位在「調解」而非「召回」，對設計記憶系統很有啟發。

    疑問

    • 出題、評分與受測的模型重疊：Gemini-3.1-pro 出題又拿第一，Gemini-3.1-flash-lite 評分又受測。最好用不同家族的模型重出題目或重評分，檢查名次是否穩定。
    • CUPMem 的評估：在同一個評測上診斷、設計、評估；schema 與評測類別高度重疊；強在 PR 弱在 IPA；沒有在其他評測上檢查副作用。
    • 人工驗證的覆蓋：只驗了兩個閉源模型的回答，沒有驗 CUPMem 和記憶框架，而 CUPMem 的高 PR 分正是最需要確認的。
    • 統計：主表沒有信賴區間；200 題下 1 題 = 0.5 個百分點，許多系統的差距在幾個百分點內。
    • 生態效度：題目由「邏輯攻擊者」刻意寫得隱晦，真實使用者的更新可能更直接，也可能更模糊；干擾 session 不屬於同一個人。
    • 記憶框架都用預設設定與 GPT-4o-mini：結論是「現有框架在預設設定下」不足，換更強的骨幹模型時是否仍然如此未知。

    可以延伸的方向

    • 讓 Zep、FadeMem 這類系統在寫入時也查詢「受影響的屬性」，而不只是相似記憶，看能補回多少 Type II。
    • 設計多次連續更新、需要撤回裁決的情境（例如石膏拆了之後又可以騎車）。原文的 query 時間稽核已經考慮到狀態會過期，但評測裡沒有「新狀態再度失效」的題目。
    • 不依賴預設 schema 的狀態推論，也是原文自述的未來方向。

    部分支持 對 LightMem 成立；推廣到「記憶框架」整體證據不足。
    主張五：寫入時裁決能大幅改善（CUPMem 8.7% → 68.0%）（§5）。
    支持證據
    Table 2，同一 GPT-4o-mini 骨幹。
    其他解釋
    提升集中在 PR（78.0／75.0）；讀取時的前提驗證器本身就針對 PR 題型，提升可能主要來自讀取端，而不是寫入時裁決。
    直接測到嗎
    測了整個系統，沒有分開寫入端與讀取端的消融。
    未測的邊界
    在同一評測上診斷、設計、評估；沒有留出集，也沒在一般記憶評測上檢查副作用；評審人工驗證沒有涵蓋 CUPMem 的輸出。
    評語
    部分支持 在 STALE 上的提升有數據；歸因給「寫入時裁決」與推廣到其他評測都證據不足。
    D研究延伸：可否證的假說研究構想，不是已驗證的貢獻

    以下是研究構想，尚未被驗證。

    假說一：CUPMem 的 PR 提升來自寫入端還是讀取端？
    研究問題
    把 CUPMem 拆成寫入時裁決與讀取時前提驗證，哪一半造成 PR 從近 0 到 75% 以上？
    可否證的假說
    若寫入時裁決是主因，「只有寫入端」的變體 PR 會接近完整版，「只有讀取端（套在 LightMem 上）」會明顯較低；反之則讀取端是主因。
    實驗情境
    用公開程式碼做三個變體：完整版；寫入端加一般 top-k 讀取；LightMem 記憶加 CUPMem 的讀取驗證器。跑全部 400 筆。
    比較基線
    LightMem、GPT-4o-mini 長上下文。
    控制變因
    GPT-4o-mini 骨幹、同一評審與評分提示詞、同一資料；每個變體 3 次執行。
    評估指標
    SR、PR、IPA 分類型準確率；另抽 100 筆 PR 回答做人工判讀，檢查「先質疑前提、但建議不佳」是否被評審放行。
    能分辨什麼
    寫入時裁決的價值對讀取時檢查的價值；也順帶檢查評審在 CUPMem 輸出上的可靠度。
    可能失敗的條件
    若兩端互相依賴（讀取驗證器需要 STALE 標記才能運作），單獨的變體會失效，需改用「關閉部分功能」的設計。
    假說二：CUPMem 的增益是否依賴 schema 對評測類別的覆蓋？
    研究問題
    CUPMem 的 10 領域 schema 與 STALE 的類別高度重疊。在 schema 覆蓋不到的屬性上，它還有效嗎？
    可否證的假說
    CUPMem 相對 GPT-4o-mini 的提升，在能對應到 schema 領域的類別上顯著大於對應不到的類別；在新生成、刻意避開 schema 領域的留出集上，提升會大幅縮小。
    實驗情境
    依 Figure 5 的 10 大類計算 CUPMem 分類別準確率；再用公開的建構流程生成 100 筆 schema 外屬性的新情境。
    比較基線
    GPT-4o-mini、LightMem、Gemini-3.1-pro。
    控制變因
    同一建構流程與審查標準、同一評審。
    評估指標
    分類別準確率與 bootstrap 信賴區間；schema 覆蓋程度（人工標註）。
    能分辨什麼
    「schema 覆蓋」對「一般性的裁決能力」。
    可能失敗的條件
    每類只有 19–54 筆，信賴區間會很寬；留出集需要人工審查才能確保衝突成立。

    術語表

    隱性衝突
    Implicit conflict：新觀測讓舊信念失效，但沒有字面上的否定，需要推理才發現。
    共指衝突
    Type I（co-referential）：新舊觀測針對同一屬性，值不相容。
    傳播衝突
    Type II（propagated）：新觀測更新另一個屬性，透過依賴關係讓舊信念失效。
    潛在狀態追蹤
    Latent state tracking：把使用者狀態當成不可直接觀測的隱變數，從對話這種部分觀測去推估。
    HMM / POMDP
    隱馬可夫模型；部分可觀測馬可夫決策過程。兩者都處理「真實狀態看不到、只看得到觀測」的問題。
    SR / PR / IPA
    State Resolution 狀態判定、Premise Resistance 前提抵抗、Implicit Policy Adaptation 隱性策略調適。
    草堆
    Haystack：把關鍵證據藏在大量無關內容中的長上下文測試設計，源自「大海撈針」。
    LLM-as-judge
    用 LLM 依評分規則判斷回答是否正確。
    Cohen's κ
    扣除隨機一致後的評分者一致性指標，1 為完全一致。
    現況調解缺口
    Current-state adjudication gap：新證據能被存入與取回，卻沒有成為回答時的依據。
    寫入時裁決
    Write-side adjudication：在記憶寫入時就決定舊記憶是否仍有效，而不是等到回答時。
