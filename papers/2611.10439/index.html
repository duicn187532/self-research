    01

    閱讀路線

    原文 §1–6

    先預測：同一使用者的兩個 Agent 能分享偏好嗎？不同使用者但同一 Agent 可讀私人工作習慣嗎？當公開 lesson 過時時，Scope 能否處理？

    想像學校有四種借書證，借得到不代表書裡的建議現在仍對。

    先掌握三個問題：誰受益、誰可看、如何避免跨使用者資訊洩漏。再讀方法、表格與消融。

    讀完應能重建 Equation (1)、四 Scope 及 Dual-stream，再判讀 pass rate/Δ 的分母，設計情境切換反例。

    自我檢測
    本篇核心問題是什麼？

    把經驗分給受益又被允許存取的 User–Agent 配對。

    02

    問題與貢獻

    原文 §1–2

    原文 §1

    原有單一個人儲存無法充分轉移經驗；全域共享池容易混入不適合及受保護的內容。MixUA 對每個 lesson 學習不同讀者集合。

    一張公開的解題技巧很好，但私人日記不該被大家一起拿走。

    Self-evolving 只改善單個 Agent；Cross-learning 允許不同 User 和異質 Agent 傳遞 lesson，須同時滿足 Transferability、Audience Selectivity、Confidentiality。

    作者提出 MixUA 四種 Scope 與 CrossLearnBench，不是時間性知識圖演算法。評測同時涵蓋 utility、preference retention 和 privacy。

    自我檢測
    為何不能所有記憶都選 Global？

    可能不適合所有讀者，且會暴露個人資訊。

    03

    四種 Scope

    原文 §3.2、Figure 16

    原文 §3.2；本站以集合寫出可見視圖形式化
    \[V(u,a)=P_{u,a}\cup U_u\cup A_a\cup G\]
    Scope例子讀者
    Pair只與指定 Agent 使用的習慣該 User–Agent
    User使用者文件格式偏好該 User 的所有 Agent
    AgentAgent 專有工具技巧所有 User 的該 Agent
    Global可重用的公開 Bug 解法所有 User × Agent

    想像紙條只給你與助手、給你的所有助手、給某種助手，或者給所有人。

    Pair={u}×{a}、User={u}×A、Agent=U×{a}、Global=U×A。User 和 Agent 走不同維度，不是一條上下級排序。

    四種集合形成菱形偏序；User 與 Agent 互不可比較。Pair 最窄，Global 最廣；擴大使用者軸才可能造成跨使用者揭露。

    自我檢測
    User 與 Agent Scope 是包含關係嗎？

    不是；兩者沿不同的使用者、代理軸擴展。

    04

    Equation (1)：誰能使用

    原文 §3.1、Eq. (1)

    Equation (1) — 原文原文
    \[\operatorname{Aud}(e)\subseteq\mathcal{G}(e)\cap\mathcal{D}(e)\]
    Aud(e)
    授權使用此段記憶的 User–Agent 配對
    𝒢(e)
    在這些配對下 lesson 有用的集合
    𝒟(e)
    不會違反來源使用者揭露邊界的集合

    一條記憶要『對他有用』而且『能安全告訴他』才能共享。

    Aud(e) 是實際可讀的配對；G(e) 是適用配對；D(e) 是在揭露邊界內可讀的配對。三者皆為配對集合。

    包含式是設計上的必要約束，而不是作者能精確算出真實 G、D 的證明。LLM Scope 分配只是近似。這裡的 generalization 不等於時間有效性。

    自我檢測
    Aud(e) 是否必須等於 G(e) ∩ D(e)？

    不必；原文用包含而非相等，實際 scope 可能保守。

    05

    Dual-stream Memory Writing

    原文 §3.3、Fig. 3

    原文處理順序：Task → Trajectory + Verifier → Privacy Splitter → Isolated Writer → Scoped Memory。記憶附來源任務、配對、round、outcome；同一任務成功與失敗均可帶來 lesson。

    把公開心得與私人日記先分開，再交給不同的整理員。

    一段 trajectory 和 verifier outcome 被 privacy splitter 分成 reusable 與 protected。兩條資料流交由隔離的 writers，產生 situation、lesson、scope、provenance。

    protected writer 不可寫入 Agent／Global。這是資料流層的權限限制，不只是讓同一個 LLM 自我宣稱沒有洩密；splitter 錯分仍是風險。

    自我檢測
    Protected stream 最多可以放哪些 Scope？

    只能放來源 User 的 Pair 或 User。

    06

    Periodic Store Review

    原文 §3.3、Appendix H

    原文 Appendix H

    即使兩筆內容語句相似，只要一個說 do、另一個說 do not，或適用情境不同，不能簡單合併。原始 provenance 要保留。

    每一輪整理抽屜，把放太窄的紙條移動，重複的才合併。

    作者每輪可選擇重新分配 Scope，再於同 destination 合併 situation 與建議相同的條目；保護資料的跨使用者上限不變。

    原文的 re-scope 並非 temporal decay，也沒有圖穩定性或重新啟用規則；Review 每輪讀整庫帶來擴展成本。

    自我檢測
    Review 和遺忘有相同目的嗎？

    不完全；Review 重新分配讀者並消除重複，不等於時間性失效判斷。

    07

    授權後再檢索

    原文 §3.4、Appendix C–D

    本站抽象化相似度排序（非原文公式）本站推導
    \[\operatorname{score}(e,q)=\cos(\operatorname{Emb}(s_e),\operatorname{Emb}(q))\]

    其中 sₑ 為 situation。Scheduled：40k chars／Scope；Random：20k chars／Scope（Appendix D）。

    先進自己有權讀的書房，再找和題目最相近的紙條。

    每對 (u,a) 只看 Pair/User/Agent/Global 四個分區，用 situation embedding 與 task prompt 的 cosine similarity 排序，依每 Scope 的字元預算帶入 context。

    作者使用平面分區與 Titan Text Embeddings v2，不是 Temporal Graph。語意相近僅代表相關性，不保證在當前情境與時間仍有效。

    自我檢測
    高相似度是否足以證明 lesson 還有效？

    不行；相似度不直接檢測時間性失效。

    互動 Scope 模擬器

    原文 §3.2、Appendix C（本站示意）

    本站示意資料 先試 Pair(A,X) → 查詢(B,Y)，再試 Agent / Global。Protected+Global 應被阻止寫入。

    切換 User、Agent 與 Scope，觀察有哪些配對拿得到紙條。

    你可手動選擇起源配對、資料流、儲存 Scope 與讀取配對；系統依正式集合定義判斷誰能讀。

    本互動只重現 audience 授權與 protected stream 限制，不是原文的 LLM Scope 預測或 benchmark 數值。

    自我檢測
    來源 A–X 的 User 記憶可被 B–X 讀到嗎？

    不行，因為 User Scope 必須同一使用者。

    CrossLearnBench 評測設計

    原文 §4–5.1、Appendix B/E/F

    指標代表什麼
    Pass rate原資料集 verifier 通過率
    Preference retentionround 1 告知、後續不重複的文件規格保持率
    Privacy probe私人事實或偏好是否到不該讀的分區
    Turns / Cost資源與效率；單位需查表

    除了看作業是否通過，也檢查偏好有沒有記住、私事有沒有跑出去。

    以七個既有 agent task sets 為底；額外植入 synthetic user preferences 和 private facts。原 verifier 測 pass，文件規格測 preference，探針檢查越界資訊。

    固定排程每輪 171 次、三輪；另以 20 個 held-out tasks、140 次嘗試檢查；隨機排程則 546-task 池、每輪 60 題、八輪。不能混用不同分母的指標。

    自我檢測
    CrossLearnBench 的效能指標只看 accuracy 嗎？

    不是，還有偏好、隱私、資源成本與跨配對轉移。

    主結果與分母

    原文 §5.2、Table 2、Figure 6

    Table 2 部分列：主表的不同指標
    MethodR3 %Δ ppPref %
    No memory72.0—11
    Pair only77.6+4.380
    Global only85.5+11.511
    MixUA LLM88.1+15.390
    MixUA LLM+review89.8+16.389

    分母警告 89.8−72.0=17.8 pp，但 Table 2 的 Δ 是 +16.3 pp，因為其分母與比較輪次不同。

    把記憶放對抽屜，常能兼顧答題和偏好，但必須看清楚成績怎麼算。

    主表第三輪 Pass R3：No memory 72.0%、Pair only 77.6%、Global only 85.5%、MixUA LLM+review 89.8%。Δ=+16.3 pp 是 R2–R3 對 no memory 的跨輪增益，不是 R3 差。

    Random 首見任務的 gain 是 MixUA +10.1 pp、Global +5.5 pp。私人事實探針中的極低越界比例不代表整體資訊洩漏率為零；偏好洩漏是另外的指標。

    自我檢測
    為何 Δ 不等於 R3 兩個 Pass 相減？

    Δ 是 R2–R3 的配對增益，R3 是單輪絕對 Pass。

    原文 §5.3、Tables 3–4

    Table 4：移除一種 Scope 的消融
    移除Δ ppPreference %

    Table 3 也比較每 Scope 1k–40k 字元。縮小 context 仍可能勝 Global-only，但偏好保留會下降；不可只看 pass rate。

    如果抽掉一種抽屜，有些特定工作就更常失敗。

    MixUA LLM（無 review）Δ=15.3；去 Global→9.0、去 User→10.5、去 Agent→14.8、去 Pair→15.2。去 User 後偏好 90→81。

    作者另以 crowded scope probes 讓 Agent/Pair 優勢顯現。單一分區法的 writer 仍可用文字模擬更細的情境，不能誤以為其他 baseline 完全不含條件。

    自我檢測
    哪一 Scope 的移除使 Δ 下降最多？

    Global；跨不同 User 與 Agent 的 lesson 主要由它傳遞。

    12

    限制、研究 Gap 與假說

    原文 Limitations、Ethical Considerations；本站延伸

    本站研究假說，非 MixUA 原文公式本站推導
    \[\operatorname{Use}(e,u,a,c,t)=\operatorname{Authorized}(e,u,a)\land\operatorname{Valid}(e,c,t)\]

    對照：Scope-only、Scope+Recency、Scope+Semantic、Scope+Validity；固定資料、配對權限、token budget。Metric：outdated adoption、reactivation recall、answer accuracy、cost。原文沒有直接驗證時間性失效不代表 MixUA 必定失敗。

    能讀某張紙條，不代表多年後內容仍對；這是不同的困難。

    原文四個 Scope 不含 Team/Department 任意群組；只測合成使用者。Review 全庫成本、同意撤回、惡意貢獻都沒有完整實驗。

    本站研究假說：同一合法 Audience 下，加入 Contextual/Temporal Validity Gate 能否降低過時 lesson 採信，且在 A→B→A 世界狀態回復時恢復舊經驗？需控制原有 Scope、檢索器與 LLM。

    自我檢測
    MixUA 可直接判斷世界狀態 A→B→A 的重新啟用嗎？

    原文沒有直接設計或驗證此機制；不能把 Audience Scope 當 Temporal Validity。

    A　方法重建：輸入、狀態、順序

    原文 §3、Appendix C Algorithm 1 Input: (t,u,a), trajectory τ, verifier y；State: 四 Scope 分區中的 (situation,lesson,scope,provenance)；Output: 下一輪的授權記憶上下文。

    1. 從 V(u,a) 取 situation 相似的 lesson（按每 Scope budget）
    2. 執行 task 並收集 trajectory、verifier outcome
    3. Split reusable／protected；writer 經由受限的分區寫入
    4. 選用 Store Review 重新分配和合併；再進下一輪

    本站假設 可在授權後增添時間／情境有效性 gate；作者沒有此一模組。

    C　主張與證據：推論界線

    支持：Table 2 顯示效益與偏好的取捨；Random 首次任務 +10.1 pp 支持跨任務學習；Table 4 移除 Scope 與專門 probe 支持四 Scope 角色分工。

    替代解釋：不同 Scope 得到的 context 量及 writer 適配也能影響結果。作者用 Budget 變化縮小此疑慮，但不能把所有相關性都說成單一模組的因果效果。

    未直接測到：真實隱私同意與撤銷、惡意記憶、時間性失效後重新啟用。低探針洩漏率不代表無資安風險。

    D　可否證的研究假說

    本站研究構想 H1：在相同合法 Audience 下，Scope+temporal/context validity 比 Scope-only 更少把過期 lesson 當現況用。若相同或更差，假說不成立。

    H2：A→B→A 的世界狀態切換中，保留歷史並可重新啟用的門控比單向刪除在 A 恢復時有更高有效召回；若召回沒有改善或錯答案增加，假說不成立。

    共同控制：同一 User–Agent 配對、任務、LLM、檢索 budget 與記憶抽取。分別報失效採信率、再啟用 recall、成功率、成本和延遲。

    附

    重要術語

    Audience scope
    記憶可被哪幾個 User–Agent 配對讀取。
    Generalization
    lesson 對哪些讀者有用，不等於時間有效性。
    Disclosure boundary
    隱私允許被揭露的範圍。
    Situation
    lesson 適用情境文字，供向量檢索。
    Provenance
    原始任務、Agent–User、round、outcome。
    Review
    重分 Scope 及合併，不是 temporal decay。
