    01

    三分鐘結論

    原文 Abstract、§1、§5

    一句話

    多使用者、多 Agent 共用記憶時，問題不是「要不要分享」，而是每條 lesson 該給哪些 User–Agent 配對讀。MixUA 讓 LLM 為每條 lesson 選一個讀者範圍：Pair／User／Agent／Global。

    Table 2 與 §5.2；scheduled 設定，三次重跑平均
    要記住的數字MixUA（LLM + review）最佳單一 Scope 對照
    第 3 輪通過率（No memory 72.0%）89.8%Global only 85.5%
    Δ：R2–R3 相對 No memory 增益+16.3 ppGlobal only +11.5 pp
    Δcross：只有「不同 User 且不同 Agent」做過的題+13.9 ppGlobal only +8.9 pp
    偏好保留（第 1 輪說一次，之後不再說）89%Global only 11%；Pair only 80%
    私人事實落入禁止分區（每變體約 18k 次探針）4 個變體中 3 個為 0摘要上限：≤0.02%

    讀法：單一 Scope 只能二選一——Global 衝分數但記不住偏好，Pair 記得偏好但幾乎不轉移經驗；MixUA 的主張是四種 Scope 分工後兩者兼得。

    全班共用一本筆記會學得快，但每個人的私事和習慣不能寫進共用那本。

    先抓三個問題：lesson 對誰有用（generalization）、可以讓誰看（disclosure）、讀取時怎麼只拿到被允許的部分（retrieval）。後面章節依序回答。

    主張的強度要分開看：效用領先 Global only 約 5 pp，但對最強對照「Global only + protected stream」只多 +3.1 pp（Δ）；真正拉開差距的是偏好保留（89% vs 15%）。精讀重點是 Table 2 各欄的分母與比較對象。

    自我檢測
    MixUA 最大的優勢到底是分數還是偏好？

    兩者都有，但對最強基線（Global + protected stream）分數差距只剩約 3 pp，偏好保留則是 89% 對 15%，差距主要在個人化。

    02

    問題與貢獻

    原文 §1、Table 1

    原文 §1：三個性質

    Transferability：任何人發現的 lesson 都有機會讓全體受益。Audience selectivity：每條 lesson 有自己的有效讀者範圍。Confidentiality：每條 lesson 有揭露邊界，超過就會暴露來源使用者的私人資訊。

    依 Table 1 歸納；原文以「fixed／policy／learned」區分分享規則
    既有設計誰讀得到MixUA 的差異
    MemGPT／A-Mem／MIRIX固定為單一配對或使用者讀者範圍逐條學習
    G-Memory／SkillClaw／FederatedSkill固定共享或廣播保留個人分區與隱私上限
    Collaborative Memory／AIM由存取政策決定政策之外還判斷「對誰有用」

    好的解題技巧要分享出去，但你的日記不能因此被大家看到。

    Self-evolving agent 只從自己的經驗變強；本文的 cross-learning 是獨立的 User 與異質 Agent 互相學。貢獻有三：MixUA 記憶系統、CrossLearnBench 評測、以及「增益來自跨 User/Agent 經驗、四 Scope 各有分工」的實驗發現。

    新意在把「分享給誰」從系統設計時就寫死，變成每條記憶的學習決策（learned per entry）。它不是新的檢索演算法或時間性知識圖；檢索仍是一般的向量相似度。

    自我檢測
    為何不能把所有記憶都放 Global？

    有些 lesson 只對特定使用者或 Agent 有用（放 Global 會干擾別人），有些含私人資訊（放 Global 會外洩）。

    03

    四種 Scope：兩條軸、四個格子

    原文 §3.2、Fig. 16、Appendix H

    原文 §3.2 的可見視圖，以集合寫出形式化
    \[V(u,a)=\underbrace{P_{u,a}}_{\{u\}\times\{a\}}\cup\underbrace{U_u}_{\{u\}\times\mathcal{A}}\cup\underbrace{A_a}_{\mathcal{U}\times\{a\}}\cup\underbrace{G}_{\mathcal{U}\times\mathcal{A}}\]
    Scope誰讀得到原文舉例的內容
    Pair這個 User 用這個 Agent同一人對不同 Agent 的要求互相衝突（對囉嗦的要簡潔、對簡潔的要細節）
    User這個 User 用任何 Agent文件格式等個人偏好
    Agent任何 User 用這個 Agent工具呼叫的怪癖、這個 Agent 常犯的錯
    Global所有人函式庫缺陷，甚至某一題的解法
    原文 Appendix H：最容易誤解的規則

    Writer 被要求「依 Scope 放，不依廣度放」：只關於單一任務的事實也屬於 Global，因為它不綁定任何 User 或 Agent。Scope 回答「誰該讀」，不是「這條知識多通用」。

    紙條可以只給「你和這位助手」、「你的所有助手」、「這位助手的所有主人」，或「所有人」。

    兩條軸各有「只限來源」與「開放全體」兩種選擇，組合成四格。User 與 Agent 不是上下級，而是沿不同軸放寬；Pair 最窄、Global 最寬。

    四者以包含關係形成菱形偏序，User 與 Agent 不可比較。只有放寬「使用者軸」會讓別的使用者讀到，所以隱私閘門只需管 Pair→Agent、User→Global 這種跨使用者的步驟。

    自我檢測
    「只對第 37 題有用的修正方法」應放哪個 Scope？

    Global。它不屬於任何特定 User 或 Agent；Scope 看讀者，不看通用程度。

    04

    Equation (1)：誰能讀

    原文 §3.1、Eq. (1)

    Equation (1) — 原文原文
    \[\operatorname{Aud}(e)\subseteq\mathcal{G}(e)\cap\mathcal{D}(e)\]
    Aud(e)
    實際授權讀取 e 的 User–Agent 配對
    𝒢(e)
    generalization scope：e 對其有效的配對
    𝒟(e)
    disclosure boundary：讀到 e 也不會暴露來源使用者的配對

    一張紙條要「對他有用」而且「讓他看也安全」，才能給他。

    三者都是配對集合。目標是讓有用的知識盡量送到每個能用的配對，同時私人知識留在擁有者身邊。

    用的是包含（⊆）而非等號：系統可以保守，但不能越界。真實的 𝒢、𝒟 不可觀測，MixUA 用 LLM（Writer、Review）近似，所以 Eq. (1) 是設計約束，不是可證明的保證——隱私錯誤會來自 splitter 或 writer 的誤判。

    自我檢測
    Aud(e) 必須等於 𝒢(e) ∩ 𝒟(e) 嗎？

    不必。原文只要求是子集合，放得比較窄只是少分享，不違反約束。

    05

    Dual-stream 寫入：先分流，再寫

    原文 §3.3、Fig. 3、Appendix C、H

    流程：軌跡 τ + verifier 結果 y → Privacy Splitter → 兩個隔離的 Writer → 帶 Scope 的記憶條目。每條目 = situation（何時適用）＋ lesson（怎麼做）＋ scope ＋ provenance（來源任務、配對、輪次、結果）。

    依 Appendix H 的 splitter／writer prompt 整理
    Reusable streamProtected stream
    內容可轉移的技術教訓：需求、失敗、修法、verifier 說了什麼；保留指令、旗標、錯誤訊息關於這個使用者的事：身分、雇主、團隊、時區、輸出與命名習慣
    去識別泛化而非刪除：/home/alice/proj/run.sh → <path>/run.sh不需要，只有本人讀
    可寫入任何 Scope只有 Pair 或 User
    永不儲存身分證號、任何憑證的值同左

    先把「公開心得」和「私人日記」分開，交給兩個互相看不到的整理員。

    關鍵是「不靠 Writer 自己標記」：每條記憶的保護等級由它來自哪一條資料流決定，所以讀過私人內容的 Writer 根本寫不出共享條目。Writer 會看到 verifier 結果，因為「為什麼失敗」才是可學的。

    Writer 的證據規則：verifier 判定優先於 Agent 自己的宣稱；graded failure 是強證據，timeout 或錯誤則不構成任何證據。這是權限在資料流層的硬限制；剩下的風險集中在 splitter 錯分（把私事放進 reusable）。Splitter、Writer、Review 都用 Claude Opus 5，隱私判官用 Sonnet 5。

    自我檢測
    Protected stream 的條目最寬可以到哪個 Scope？

    User（來源使用者的所有 Agent）。永遠進不了 Agent 或 Global。

    06

    Periodic Store Review：兩階段整理

    原文 §3.3、Fig. 3、Appendix H

    Appendix H 的 review prompt
    階段做什麼規則
    1．重分 Scope看整庫條目，一次移動一格：Pair→User/Agent→Global，或反向收窄問「這條服務誰」而非「誰產生的」；同一事實出現在不同 Scope 是放寬的理由；收窄有代價，只有該使用者在別的 Agent 想要不同做法時才把 User 降為 Pair；protected 條目上限仍是 User
    2．合併同 Scope、同擁有者內，合併描述同一情境且建議相同行為的條目字面相似不夠；do 與 do-not、不同條件下成立的事實、保留語氣與斷言語氣都要分開；只刪冗字，不加新內容，保留所有來源

    導讀補充 階段 1 的輸入刻意不含次數與成敗，只憑文字判斷；但 Fig. 3 畫的是「獨立來源 → 升級、失敗或矛盾 → 降級」。讀圖時以 Appendix H 的實際輸入為準。

    每輪結束整理抽屜：放錯的紙條換抽屜，重複的才合併。

    Writer 一次只看一條軌跡，容易把 Scope 定得太窄或太寬，也會寫出重複條目；Review 用整庫視角修正。效果：LLM Writer 的 Δ 15.3→16.3，agentic Writer 12.8→14.0，偏好外洩 4.8%→3.6%。

    Review 不是遺忘機制：沒有時間衰減、也沒有「過期後重新啟用」。它每輪讀整個庫，作者在 Limitations 承認全球規模下這一步無法一次跑完。

    自我檢測
    Store Review 會判斷 lesson 是否已經過時嗎？

    不會。它只重新分配讀者範圍、合併重複；時間有效性不在本文範圍。

    檢索：先限定可讀分區，再排相似度

    原文 §3.4、Appendix C

    本站把原文文字敘述寫成式子（非原文公式）導讀補充
    \[\operatorname{score}(e,q)=\cos\big(\operatorname{Emb}(s_e),\operatorname{Emb}(q)\big),\quad e\in V(u,a)\]

    se 是條目的 situation，q 是任務 prompt；每個 Scope 各自排序，填到該 Scope 的字元預算為止。結果以「# Learned memory: <scope>」分段放進 prompt，不寫進任務工作目錄。

    先走進自己有鑰匙的四個房間，再在裡面找和題目最像的紙條。

    Store 是平面分區：一個 Global、每位 User 一個、每個 Agent 一個、每個配對一個。授權靠「只查 V(u,a) 這四區」達成，不是事後過濾。Embedding 用 Titan Text Embeddings v2。

    另一個變體是 file-based：把四區各放成一個檔案讓 Agent 自己 grep，增益接近（+14.5 pp），但回合數 13.9→17.0、偏好保留 90%→75%。相似度只代表相關，不保證該 lesson 在當前情境或時間仍成立。

    自我檢測
    每個 Scope 各自有字元預算，有什麼好處？

    大量 Global 任務條目不會把少量的 User／Pair 偏好擠出 context；這也解釋了 Pair only 在長期隨機實驗中偏好保留下滑（見第 10 節）。

    09

    CrossLearnBench：在既有任務上加兩層測試

    原文 §4、§5.1、Appendix B、E

    層做法量什麼
    任務七個既有資料集（AutoCodeBench、FeatureBench、SpreadsheetBench、SWT-Bench、USACO、Terminal-Bench 2.0、VMax），Docker 中執行，verifier 不改Pass rate
    隱私每位合成使用者有 9 項 PII 與 14 類 Pew 調查事實；同一類對甲是私密、對乙可能不是。事實藏在 form.txt、notes.txt 等中性檔名，評分前刪除Exposure（打開檔案）、Leakage（出現在禁止分區）
    偏好完成後要寫一份摘要文件：檔名、簽名日期格式、段落順序、禁用標記；只在第 1 輪告知Preference retention
    設定規模
    Scheduled（主結果）5 users × 7 agents，每輪 171 次嘗試 × 3 輪，重跑 3 次；之後凍結記憶跑 20 題 held-out（140 次）
    Random546 題池，每輪抽 60 題隨機配給配對，8 輪，2 個 seed
    User scaling20 與 100 位使用者，各 1 個 seed

    Agent 是七種 LLM × harness 組合：Claude Code（Opus 5／Sonnet 5）、Hermes 與 OpenClaw（Sonnet 5）、Codex（GPT-5.6 Sol／Luna／Terra）。

    除了看作業有沒有做對，也偷偷放了私人資料和個人要求，看記憶會不會亂傳、會不會記住。

    設計巧思：簽名日期格式依 harness 不同，等於故意製造「同一使用者對不同 Agent 有不同要求」的情境，Pair Scope 才有用武之地。Scheduled 讓同一題被同配對、同 User 或同 Agent、或完全不同的配對再遇到，才能拆出增益來自誰。

    Scheduled 依賴題目重複出現，所以 Random 實驗才是「新題目也有幫助嗎」的關鍵證據。偏好只測格式類要求（可自動解析），不涵蓋語氣或內容層級的個人化；隱私洩漏由 LLM 判官（YES/NO，含改寫）判定，判官本身的漏判率未報告。

    自我檢測
    為什麼還需要 Random 任務實驗？

    Scheduled 讓同一題重複出現，增益可能只是記住解法；Random 中 821 次嘗試有 526 次是沒人做過的題，只能靠別題學到的經驗。

    要對最強基線比：Global + protected stream 也能拿到 +13.2／+12.6，MixUA 多 +3.1／+1.3 pp；Table 2 的星號是相對 No memory 的 McNemar 檢定，不是兩者之間的檢定。成本約為 No memory 的 11 倍（0.30→3.43）。Fig. 5 的 20／100 users 擴展實驗（單 seed）中，MixUA 對 Global only 的差距均標 n.s.。

    自我檢測
    為何 Δ 不等於兩個 R3 相減？

    R3 是第 3 輪的單輪通過率；Δ 是第 2–3 輪合併計算、相對 No memory 的增益，口徑不同。

    拿掉公共抽屜，大家學不到別人的經驗；拿掉個人抽屜，助手就忘了你的習慣。

    Global 撐效用、User 撐偏好。拿掉 Agent 或 Pair 在主指標上幾乎看不出差別，所以作者另做「擁擠預算」與「工作情境外洩」探針，才顯示兩者的角色。Held-out 遮罩也印證分工：只給 Global 或 Agent 時偏好保留 8–12%，跟空記憶差不多。

    「是不是只是塞了更多 context？」：每 Scope 10k 時每題只送 22.8k 字元（不到 Global only 的 60%），Δ 仍較高（13.1 vs 11.5）。但注意 Agent／Pair 的價值是靠作者自建的探針證明，主 benchmark 並不需要它們；而且被移除的 Scope 內容仍可寫進其他 Scope（例如 Global 條目寫「當 agent X…」）。

    自我檢測
    移除哪個 Scope 讓 Δcross 下跌最多？為什麼？

    Global（13.0→4.6）。Δcross 只算「不同 User 且不同 Agent」做過的題，只有 Global 能把那些經驗帶過來。

    原文 Limitations、Ethical Considerations；本站延伸

    作者承認的限制本站補充的證據缺口
    使用者與 Agent 被視為彼此獨立；團隊、部門等層級的共享秘密無法表達全部是 5／20／100 位合成使用者，偏好只有格式類
    讀者只有「一個」或「全部」，沒有群組 Scope隱私由 LLM 判官判定，判官漏判率未報告

    本站研究假說，非 MixUA 原文公式導讀補充
    \[\operatorname{Use}(e,u,a,c,t)=\underbrace{\operatorname{Authorized}(e,u,a)}_{\text{MixUA 處理}}\land\underbrace{\operatorname{Valid}(e,c,t)}_{\text{本文未處理}}\]

    能讀某張紙條，不代表紙條上的建議現在還對；這是另一個問題。

    MixUA 解的是「誰能讀」，不是「這條還成立嗎」。當函式庫升版、使用者換了偏好，Global 裡的舊 lesson 仍會因為高相似度被取出。

    C　主張與證據：推論界線

    支持得較好：四 Scope 兼顧效用與偏好（Table 2、Fig. 4b）；Global 承載跨使用者轉移（Table 4 的 Δcross 4.6）；偏好住在 User／Pair（Fig. 7b 遮罩）；增益不只是 context 變多（Table 3）。

    較弱或有替代解釋：對 Global + protected stream 的效用優勢僅約 3 pp 且未直接檢定；Agent／Pair 的必要性主要來自作者自建探針；Store review 的改善幅度（約 1 pp）與跑次間標準差（1.1–1.8）同級。

    未測：真實使用者與同意撤回、惡意 lesson、群組讀者、時間性失效。低探針洩漏率不等於可上線——作者也明說不能據此跳過存取控制與隱私審查。

    D　可否證的研究假說

    本站研究構想 H1：相同合法 Audience 下，Scope + validity gate 比 Scope-only 更少把過期 lesson 當現況用；若相同或更差，假說不成立。

    H2：A→B→A 狀態切換中，保留歷史並可重新啟用的閘門，比單向刪除在 A 恢復時有更高有效召回；若召回沒有改善或錯答增加，假說不成立。

    H3：引入群組 Scope（團隊）後，跨使用者洩漏率不上升、團隊內 Δ 上升；需要新的「群組內私密」探針。

    共同控制：同一配對、任務、LLM、檢索預算與記憶抽取；分別報告過期採用率、重新啟用 recall、成功率、成本與延遲。

    重要術語

    Cross-learning
    獨立的使用者與異質 Agent 互相從對方經驗學習。
    Audience（Aud）
    實際授權讀取一條記憶的 User–Agent 配對集合。
    Generalization scope（𝒢）
    lesson 有效的配對；不等於時間有效性。
    Disclosure boundary（𝒟）
    不暴露來源使用者時，最寬可放的範圍。
    Situation
    lesson 何時適用的文字，用來做向量檢索。
    Provenance
    來源任務、配對、輪次與結果；讓檢視與刪除成為可能。
    Δ／Δcross
    R2–R3 相對 No memory 的增益；Δcross 只算「不同 User 且不同 Agent」做過的題。
    Store review
    重分 Scope ＋合併重複，不是遺忘或時間衰減。
