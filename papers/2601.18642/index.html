    01

    問題：Agent 為什麼需要「忘記」

    想像你有一個超級大的玩具箱，每天都把新玩具丟進去，從來不整理。過了一陣子，你想找最喜歡的小汽車，卻被一堆壞掉的積木和舊貼紙擋住，翻半天都找不到。

    AI 助理也有這種「記憶箱」。FadeMem 教它像人一樣，把不重要的東西慢慢忘掉，重要的東西留在好找的地方。

    大型語言模型的上下文視窗（context window）有限，所以長期對話的 agent 會把過去的資訊存在外部記憶裡，需要時再撈回來。現有做法大多「只存不刪」，帶來兩個問題：

    • 資訊過載：記憶越來越多，檢索時被大量過時、瑣碎的內容干擾，真正重要的反而撈不到。
    • 新舊矛盾：使用者昨天說住台北、今天說搬到台中，兩筆都在，模型不知道該信哪一筆。

    作者的主張：主動遺忘不是缺陷，而是記憶系統該有的功能。人腦就是這樣運作，不常用、不重要的記憶會淡化。

    問題設定是長期互動 agent 的外部記憶管理。現有系統（MemGPT 的分頁式虛擬上下文、Mem0 的抽取與更新）主要處理「怎麼存、怎麼取」，對保留策略（retention policy）的處理偏二元：保留或被顯式覆寫刪除。結果是記憶庫單調成長，檢索的 precision 隨時間下降，矛盾事實並存。

    FadeMem 把保留問題建模成連續的「記憶強度」隨時間衰減，衰減速率由重要性調節，並加上兩個 LLM 驅動的整理操作（衝突解決、融合）。要評估的是兩件事的 trade-off：儲存量減少多少，關鍵資訊與推理能力保留多少。

    論文怎麼說 摘要

    作者指出現有 agent 記憶缺少人類那種選擇性遺忘，提出以雙層記憶階層搭配不同衰減速率的架構；保留程度由自適應指數衰減函數決定，並受語意相關性、存取頻率、時間模式調節。

    自我檢測
    「只存不刪」的記憶系統，會在哪兩方面變差？

    一是檢索品質：雜訊越多，相關記憶越難排到前面。二是一致性：互相矛盾的舊事實和新事實並存。順帶還有儲存與檢索成本隨時間線性成長。

    這篇論文要證明的核心 trade-off 是什麼？

    少存很多（摘要說減少 45% 儲存），但關鍵事實保留率與多跳推理表現不輸、甚至勝過不刪除的基線。

    02

    核心架構：雙層記憶

    FadeMem 的記憶有兩個抽屜。上層小抽屜放剛學到的事，東西很快就會不見。下層大抽屜放很重要、常常用到的事，東西會放很久。

    有一位小管家會幫每件事打分數。分數高就搬到大抽屜，分數掉下去就搬回小抽屜。

    每筆記憶都有一個「強度」\(v_i(t)\)，隨時間下降。兩層的差別在於下降的形狀：LML 衰減慢、尾巴長，SML 衰減快。記憶在哪一層，由它的重要性分數 \(I_i(t)\) 決定，而且會隨時間重新評估，所以記憶可以在兩層之間移動。

    這很像人的短期記憶與長期記憶：常被想起、跟目前任務相關的內容會被「鞏固」。

    設計上的關鍵是差異化衰減：同一套衰減函數，兩層用不同的形狀參數 \(\beta\)（二手來源：LML 0.8、SML 1.2），加上重要性調節的速率 \(\lambda_i\)。層級指派是 \(I_i(t)\) 的閾值函數，並用遲滯（hysteresis）避免在邊界附近來回震盪。

    讀全文要確認：層級是否也影響檢索（例如只從 LML 檢索或加權），還是只影響衰減？兩層有沒有容量上限？

    自我檢測
    兩層記憶在數學上差在哪裡？

    同一個衰減函數，但形狀參數 \(\beta\) 不同（LML 小於 1，SML 大於 1），所以衰減曲線形狀不同 二手・待核對。

    03

    重要性分數 \(I_i(t)\)

    重要性分數二手・待核對
    \[ I_i(t) = \alpha \cdot \mathrm{rel}(c_i, Q_t) + \beta \cdot \frac{f_i}{1 + f_i} + \gamma \cdot \mathrm{recency}(\tau_i, t) \]
    符號意思
    \(c_i\)第 \(i\) 筆記憶的內容
    \(Q_t\)時間 \(t\) 時最近的對話或查詢
    \(\mathrm{rel}(c_i, Q_t)\)記憶與目前對話的語意相關性（多半是 embedding 相似度，待確認）
    \(f_i\)存取頻率。二手來源說實作上用「隨時間衰減的存取率」而不是原始次數
    \(\frac{f_i}{1+f_i}\)飽和函數：0 次是 0，次數越多越接近 1，但永遠到不了
    \(\tau_i\)記憶建立的時間
    \(\mathrm{recency}(\tau_i, t)\)新近程度，隨 \(t - \tau_i\) 指數下降
    \(\alpha, \beta, \gamma\)三項的權重。論文給的數值未查到

    小管家打分數只看三件事：這件事跟現在聊的有沒有關係？你是不是常常想起它？它是不是最近才發生？三個加起來，分數越高越重要。

    三項各管一件事：相關性回答「現在用不用得到」，頻率回答「過去常不常用」，新近程度回答「是不是新鮮事」。頻率用 \(f/(1+f)\) 而不是直接用次數，是為了避免某筆記憶被查了上百次後分數爆表、壓過其他所有因素。

    小提醒：這裡的 \(\beta\) 是頻率權重，下一節衰減函數裡也有一個 \(\beta_i\) 是形狀參數。二手來源兩者都寫成 \(\beta\)，讀原文時確認作者是否用了不同符號。

    這個形式跟 Generative Agents（Park et al., 2023）的檢索分數 recency + importance + relevance 非常像 導讀補充。差異在用途：Generative Agents 用它排序檢索結果，FadeMem 用它調節衰減速率與層級，也就是把檢索訊號回饋到保留策略。

    值得追問：\(\mathrm{rel}(c_i, Q_t)\) 依賴當前查詢，所以 \(I_i(t)\) 是非平穩的。話題一轉，一筆長期重要的記憶（例如使用者的過敏原）可能暫時拿到低分。頻率與遲滯能抵銷多少？作者有沒有做「話題切換」的分析？

    自我檢測
    為什麼頻率項用 \(f/(1+f)\)？

    飽和。讓頻率的貢獻有上限 1，邊際效益遞減，避免單一因素主導分數。

    這個分數跟 Generative Agents 的檢索分數差在哪？

    組成很像，用途不同：一個拿來排序檢索，一個拿來決定記憶衰減得多快、放在哪一層。

    04

    衰減函數：記憶如何淡出

    記憶強度二手・待核對
    \[ v_i(t) = v_i(0)\, \exp\!\big(-\lambda_i\, (t - \tau_i)^{\beta_i}\big) \] \[ \lambda_i = \lambda_{\text{base}} \cdot \exp\!\big(-\mu \cdot I_i(t)\big), \qquad \beta_i = \begin{cases} 0.8 & \text{LML} \\ 1.2 & \text{SML} \end{cases} \]

    每件記憶都像一杯冰淇淋，放著就會慢慢融化。越重要的冰淇淋，放在越冷的地方，融得越慢。大抽屜裡的冰淇淋融得慢，小抽屜裡的融得快。融到快沒有了，就丟掉。

    這是「伸展指數」（stretched exponential）衰減。兩個旋鈕：

    • \(\lambda_i\) 速率：越大忘越快。重要性 \(I_i\) 越高，\(\lambda_i\) 被 \(e^{-\mu I}\) 壓得越小，忘得越慢。\(\mu\) 決定「重要性有多大影響力」。
    • \(\beta_i\) 形狀：\(\beta < 1\) 時一開始掉得快、之後拖出長尾巴（LML，留得久）；\(\beta > 1\) 時一開始撐得住、過一陣子急速崩落（SML）。

    下面的圖可以自己調參數看看。

    Kohlrausch 型衰減。\(\beta\) 的選擇同時影響尺度：\((t-\tau)^{\beta}\) 在 \(t-\tau < 1\) 與 \(> 1\) 兩側行為相反，所以結論依賴時間單位。若單位是「天」，在第一天內 SML 其實比 LML 衰減得慢，交叉點在 \(t-\tau = 1\)。這是讀全文時值得確認的細節：論文的時間單位是什麼？是牆鐘時間還是對話輪次？

    另一點：\(\lambda_i\) 依賴 \(I_i(t)\)，而 \(I_i(t)\) 會變，所以嚴格說 \(v_i(t)\) 不是一條固定曲線。實作上應該是每步用當下的 \(\lambda_i\) 重算或增量更新，讀原文時看作者怎麼離散化。

    從半衰期反推 \(\lambda_{\text{base}}\) 導讀補充

    令 \(v = 0.5\)，得半衰期 \(t_{1/2} = (\ln 2 / \lambda)^{1/\beta}\)。Emergent Mind 整理說 \(I=0\) 時 LML 與 SML 半衰期約 11.25 天與 5.02 天 二手・待核對。代入 \(\lambda_{\text{base}} = 0.1\)：LML 是 \(6.93^{1/0.8} \approx 11.25\)，SML 是 \(6.93^{1/1.2} \approx 5.02\)，兩個數字同時吻合。所以論文很可能用 \(\lambda_{\text{base}} = 0.1\)、時間單位為天。這是推論，請對照原文。

    自我檢測
    把 \(I\) 從 0 調到 1、\(\mu = 1\)，半衰期會變幾倍？

    \(\lambda\) 變成 \(e^{-1} \approx 0.37\) 倍。半衰期正比於 \(\lambda^{-1/\beta}\)，LML 變 \(e^{1/0.8} \approx 3.5\) 倍，SML 變 \(e^{1/1.2} \approx 2.3\) 倍。用上面的圖驗證看看。

    在什麼情況下 SML 會比 LML 忘得慢？

    當 \(t - \tau < 1\)（一個時間單位內）且兩者 \(\lambda\) 相同。因為 \(x^{1.2} < x^{0.8}\) 對 \(0 < x < 1\) 成立。把時間範圍切到 0–3 天就看得到交叉點。

    05

    層間遷移、遲滯與刪除

    層級指派與刪除二手・待核對
    \[ \text{layer}_i \leftarrow \begin{cases} \text{LML} & I_i(t) \ge \theta_{\text{promote}} \\ \text{SML} & I_i(t) < \theta_{\text{demote}} \\ \text{unchanged} & \text{otherwise} \end{cases}, \qquad \theta_{\text{promote}} > \theta_{\text{demote}} \] \[ \text{prune } i \quad \text{if } v_i(t) < \varepsilon_{\text{prune}} \ \text{or long dormancy} \]

    要搬進大抽屜，分數要考到 80 分；要被趕回小抽屜，分數要掉到 60 分以下。中間 60 到 80 分的，就留在原本的抽屜。這樣東西才不會一下搬上去、一下搬下來，搬到累死。

    升級和降級用兩個不同的門檻，中間留一段「緩衝區」，這叫遲滯（hysteresis）。冷氣的溫控也是這樣：到 26 度才開、降到 24 度才關，避免在 25 度附近一直開開關關。

    記憶強度掉到 \(\varepsilon_{\text{prune}}\) 以下，或很久沒被用到，就直接刪除。這是儲存量能降 45% 的主要來源之一。二手來源說門檻是在驗證資料上用 grid search 決定的。

    遲滯是控制論的標準手法，在這裡解決 \(I_i(t)\) 非平穩造成的層級抖動。代價是多兩個超參數，加上 \(\varepsilon_{\text{prune}}\)、\(\mu\)、\(\lambda_{\text{base}}\)、\(\alpha,\beta,\gamma\)，整個系統的可調參數不少。都在驗證集上 grid search 的話，要留意與測試集是否同分佈，以及換領域時的穩健性。

    刪除是不可逆的。讀全文時看看有沒有「軟刪除」或歸檔機制，以及被錯刪的關鍵事實造成的錯誤有多少（LTI-Bench 的 17.9% 未保留部分是什麼？）。

    自我檢測
    如果 \(\theta_{\text{promote}} = \theta_{\text{demote}}\) 會發生什麼？

    分數在門檻附近小幅波動時，記憶會在兩層之間反覆遷移，衰減形狀跟著頻繁切換，行為不穩定。

    06

    LLM 引導的衝突解決

    你本來記得「小明最喜歡藍色」，今天小明說「我現在最喜歡紅色了」。這時候小管家會把兩句話拿來比一比，發現它們吵架了，就把舊的那句「藍色」變得很淡，快要忘掉。

    新記憶寫入時分兩步：

    1. 粗篩：用向量搜尋找出少數幾筆語意相近的舊記憶。
    2. 細判：把新舊記憶交給 LLM 判斷兩者的關係。如果是矛盾，就降低舊記憶的強度 \(v\)，讓它更快被遺忘。

    先粗篩再交給 LLM，是為了控制成本：只對一小部分候選呼叫 LLM。

    值得注意的設計選擇是：矛盾時不直接刪除舊記憶，而是降低強度，讓衰減機制接手。好處是保留「時間脈絡」的可能（使用者以前喜歡藍色也是事實），壞處是在舊記憶淡出前，檢索仍可能撈到它。

    關係類別有哪些（例如相容、矛盾、補充、包含）、LLM 的 prompt 長怎樣、用哪個模型，二手來源都沒寫清楚，屬於讀全文必查項目。另有一份二手整理提到衝突解決的 macro-averaged accuracy 為 68.9% 二手・待核對，只有單一來源，數字本身也不算高。

    對照 Mem0 導讀補充：Mem0 也用 LLM 決定 ADD / UPDATE / DELETE / NOOP，但動作是離散的；FadeMem 把它接到連續的強度上。

    論文怎麼說 摘要

    摘要提到透過 LLM 引導的衝突解決（LLM-guided conflict resolution）處理新舊資訊的矛盾。

    自我檢測
    為什麼不對每一筆舊記憶都呼叫 LLM 比對？

    成本與延遲。記憶庫有 N 筆，每次寫入就要 N 次 LLM 呼叫。先用向量搜尋取 top-k，成本變成常數 k。

    「降低強度」與「直接刪除」各有什麼利弊？

    降低強度較保守，可容錯（LLM 誤判時舊記憶還在），也保留歷史；但淡出前仍可能被檢索到造成混淆。直接刪除乾淨但不可逆。

    07

    記憶融合

    你記得「小明週一去游泳」「小明週三去游泳」「小明週五去游泳」。小管家說：這三張紙條可以合成一張「小明每週一三五游泳」。紙條變少了，事情也記得更清楚。

    系統找出語意相近、時間也相近的一群記憶，請 LLM 把它們合併成一筆濃縮版。合併後的記憶：

    • 衰減得更慢，而且群組越大，衰減速率降得越多（被多次提到代表重要）。
    • 會再經過一次 LLM 驗證，確認沒有遺漏或扭曲原本的資訊。

    融合等於對記憶庫做「語意壓縮」，同時是儲存減量的來源（N 筆變 1 筆）和品質提升的來源（散落的證據被聚合，有利多跳推理）。消融實驗也支持這點：拿掉融合後，LoCoMo multi-hop F1 從 29.43 掉到 13.63，是所有元件裡掉最多的 二手・待核對。

    要查的細節：聚類用什麼相似度與時間窗？融合後衰減速率的確切公式（與群組大小的函數關係）？驗證失敗時怎麼處理？LLM 摘要可能「幻覺」出原本沒有的連結，驗證步驟的拒絕率是多少？

    論文怎麼說 摘要

    摘要提到智慧記憶融合（intelligent memory fusion）會合併相關資訊。

    自我檢測
    為什麼融合對「多跳推理」特別有幫助？

    多跳問題需要把好幾筆分散的事實串起來。檢索通常只取 top-k，分散的證據很容易缺一塊；融合後一筆記憶就帶著多個相關事實，一次檢索就拿到。

    融合的主要風險是什麼？

    LLM 合併時可能遺漏細節或捏造關聯（幻覺），而且原始記憶被取代後難以追溯。所以需要驗證步驟。

    08

    實驗結果

    三個評測 摘要：Multi-Session Chat（MSC，多段對話）、LoCoMo（超長對話記憶問答）、LTI-Bench（長期資訊保留）。比較對象至少包含 Mem0 與 MemGPT。摘要的總結是：多跳推理與檢索表現較佳，同時減少 45% 儲存。

    LTI-Bench：關鍵事實保留率與相對儲存量 二手・待核對（Moonlight 與 Emergent Mind 一致）

    45% 的儲存減少，對應 LTI-Bench 的 55.0% 儲存量（以 Mem0 的 100% 為基準）。在只存一半多的情況下，關鍵事實保留率還比 Mem0 高 3.7 個百分點。LoCoMo 多跳推理則小勝 Mem0（約 +1 F1），大勝 MemGPT。

    讀結果時要問的事 導讀補充：

    • LoCoMo 對 Mem0 的差距約 1.06 F1，有沒有多次執行的變異數或顯著性檢定？
    • LoCoMo 其他題型（single-hop、temporal、open-domain、adversarial）的結果呢？FadeMem 有沒有在某些題型輸？
    • LTI-Bench 是不是作者自建的？若是，任務設計是否天然有利於「會遺忘」的系統？
    • 儲存量之外的成本：衝突解決與融合每次都要呼叫 LLM，token 成本與延遲有沒有報告？
    • MSC 上的結果與指標是什麼？二手來源都沒提到。
    自我檢測
    「45% 儲存減少」和表中的「55.0%」是什麼關係？

    同一件事的兩種說法：相對於不刪除的基線（100%），FadeMem 只用 55% 的儲存，即減少 45%。

    消融實驗：哪個零件最重要

    LoCoMo 消融 二手・待核對。其他列的數字二手來源未提供，請讀全文補上
    變體Multi-hop F1二手描述
    FadeMem（完整）29.43—
    w/o fusion13.63降幅最大
    w/o LML-SML（單層）?所有任務都明顯下降
    w/o conflict resolution?未查到

    科學家把機器的零件一個一個拔掉，看哪個拔掉後機器壞得最嚴重。結果發現「把紙條合在一起」那個零件最重要。

    消融（ablation）就是每次拿掉一個元件，看效能掉多少，用來證明每個設計都有貢獻。拿掉融合後多跳 F1 掉了一半以上，表示 FadeMem 在多跳推理上的優勢主要來自融合，而不是衰減本身。

    有個值得深想的地方 導讀補充：拿掉融合後的 13.63 遠低於 Mem0 的 28.37。也就是說，「只有衰減與分層、沒有融合」的 FadeMem 比不遺忘的 Mem0 差很多。這暗示單純遺忘本身可能有害，要靠融合把資訊先濃縮保存，遺忘才不會傷到推理。這跟論文「遺忘是功能」的敘事有張力，讀全文時看作者怎麼解釋。

    放進研究脈絡

    以下是導讀者整理的相關工作 導讀補充，不代表論文的引用清單，讀 Related Work 時對照。

    工作核心做法和 FadeMem 的關係
    MemGPT（Packer et al., 2023）把上下文當作業系統記憶體，主記憶與外部儲存之間分頁換入換出實驗基線。有分層，但沒有連續衰減
    Mem0（2025）LLM 抽取事實，用 ADD / UPDATE / DELETE / NOOP 維護記憶主要基線。離散更新 vs. FadeMem 的連續強度
    MemoryBank（Zhong et al., 2023）已用艾賓浩斯遺忘曲線更新 LLM 記憶強度最直接的前身。讀全文看 FadeMem 怎麼和它區隔
    Generative Agents（Park et al., 2023）檢索分數 = recency + importance + relevance，加上反思（reflection）重要性分數的形式很像；反思和「融合」也有相似之處
    LoCoMo（Maharana et al., 2024）超長多段對話的記憶評測，含單跳、多跳、時間推理等題型評測資料集
    MSC（Xu et al., 2022）Multi-Session Chat，多段對話資料集評測資料集
    自我檢測
    用一句話說出 FadeMem 相對 Mem0 的新意。

    Mem0 用 LLM 對記憶做離散的增刪改；FadeMem 讓每筆記憶有連續、受重要性調節的強度並分兩層衰減，再加上融合，讓遺忘成為常態而非例外。

    11

    批判性閱讀

    優點

    • 問題重要且直觀：長期 agent 的記憶膨脹是真實痛點。
    • 機制可解釋：每筆記憶為什麼還在、為什麼被刪，都能用強度與分數說明。
    • 同時報告效能與儲存，而不是只看準確率。

    疑問

    • 超參數多（\(\alpha,\beta,\gamma,\mu,\lambda_{\text{base}},\theta,\varepsilon\)），敏感度分析做了嗎？
    • 時間單位與 \(\beta\) 的互動（見 04）。真實部署時對話密度差異很大，用牆鐘時間合理嗎？
    • 「生物啟發」到什麼程度？艾賓浩斯曲線本身是指數還是冪律在心理學上仍有爭議。
    • 不可逆刪除的風險：使用者明確要求記住的事（例如醫療資訊）會不會被忘掉？有沒有「釘選」機制？
    • LLM 呼叫成本沒有出現在「效率」的定義裡嗎？

    可以延伸的方向

    • 讓使用者或任務顯式標記重要性，作為 \(I_i\) 的一項。
    • 把刪除改成歸檔到便宜的冷儲存，需要時再喚回。
    • 用學習的方式取代手調的衰減函數。
    附錄

    術語表

    Agent memory
    LLM agent 在上下文視窗之外保存的資訊，通常存在向量資料庫，需要時檢索回來。
    Context window
    模型一次能讀的 token 數上限。超過就必須取捨或外部化。
    LML / SML
    本文的長期記憶層與短期記憶層，差在衰減形狀。
    艾賓浩斯遺忘曲線
    Ebbinghaus forgetting curve。19 世紀心理學實驗：記憶保留率隨時間快速下降後趨緩。
    伸展指數
    Stretched exponential，\(e^{-\lambda t^{\beta}}\)。\(\beta=1\) 時是普通指數衰減。
    遲滯
    Hysteresis。上升與下降用不同門檻，避免在邊界附近來回切換。
    多跳推理
    Multi-hop reasoning。答案需要串起兩筆以上分散的事實。
    F1
    Precision 與 recall 的調和平均。LoCoMo 用 token 層級的 F1 比對答案。
    消融實驗
    Ablation study。逐一拿掉元件，衡量各元件的貢獻。
    Grid search
    對超參數的候選值做窮舉組合，挑驗證集表現最好的。
