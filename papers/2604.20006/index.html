    從回想走向遺忘：Memora 如何評測個人化長期記憶

    開始閱讀　先看閱讀路線

    From Recall to Forgetting: Benchmarking Long-Term Memory for Personalized Agents

    Md Nayem Uddin、Kumar Shubham、Eduardo Blanco、Chitta Baral、Gengyu Wang

    正式來源原文 PDF

    先讀原文的研究核心

    原文 §3–4、Figure 2、§4.2 未編號 FAMA 公式 Memora 先模擬每次對話前後的記憶狀態，再生成對話與回想、推理、推薦題。答案同時要含有仍有效的資訊，並排除已更新或刪除的資訊。這是一個評測資料集與評分方法，並非新記憶代理。

    \[\begin{aligned} \lambda_q&=\frac{N_{\mathrm{forget},q}}{N_{\mathrm{presence},q}+N_{\mathrm{forget},q}},\\ \mathrm{FAMA}(q)&=\max\{0,\mathrm{MPA}(q)-\lambda_q[1-\mathrm{FAA}(q)]\}. \end{aligned}\]

    本站讀法 MPA 量「該說的是否說到」，FAA 量「不該沿用的舊資訊是否避開」；兩者同屬單題 criterion 比例。第 5 節逐符號推導，並用實際數字手算。

    這篇怎麼讀

    一套記憶系統能背出舊事，不代表它知道哪件事已經被使用者改掉。Memora 把跨 session 整合、更新／刪除與三種下游任務放在同一個壓力測試裡。

    先看問題與資料生成，再親手算 FAMA；接著讀實驗表，最後判斷合成資料和 LLM 裁判能支持多大的結論。

    學習目標：能說明研究問題、重建關鍵方法或評分、核對至少一項表格結果，並指出一個不能由證據推出的結論。可先選五歲版建立直覺，再切大學生版讀機制，最後用研究生版檢查形式與限制。

    問題：回想不等於維護現況

    原文 §1–2、Table 1核對原文 PDF ↗

    原文方法與證據

    Table 1 作者把題目所需跨越的歷史 session 數稱為 consolidation，把解題前經過的更新／刪除數稱為 mutation。LoCoMo 平均為 1.3／0.0，Memora 季度則為 28.4／14.8；後者最高到 309／94。這些是題目需求的統計，沒有測出任何模型的準確率。

    問題拆解 只檢索出舊值是資訊取得；辨認它已被改寫、不得再作現況前提，才是有效記憶維護。Memora 把兩者放入同一道題，讓「想起」與「忘掉失效版本」可以分開扣分。

    分層導讀

    朋友記得你曾說喜歡某餐廳，卻忘了你上週說已經對它過敏。答對舊回憶仍可能給出錯建議。這個比喻只說明版本衝突，沒有模擬實驗資料的生成程序。

    作者指出常用評測多考孤立回想。Table 1 中 LoCoMo 平均只需整合 1.3 個 session，更新／刪除平均 0；LongMemEval 的對應值為 1.9 與 2.0。Memora 刻意增加兩種壓力：跨 session 的 memory consolidation 和 memory mutation。這些是資料集題目層級的統計，不能讀成系統準確率。

    問題可寫成：在時刻 t 的歷史 Hₜ 中，回答 q 時需取用多個仍有效的事實，並排除已被 update/delete 的版本。這和只做 retrieval 不同；若檢索器把舊值也找回來，後續仍須裁決有效性。論文沒有提出新的記憶演算法，而是提出 benchmark 與評分。

    自我檢測
    LoCoMo 的 1.3 是準確率嗎？

    不是；它是每題平均需要整合的歷史 session 數。

    資料怎麼造：狀態軌跡先於對話

    原文 §3.1–3.3、Figure 2核對原文 PDF ↗

    原文方法與證據

    §3.1–3.3、Figure 2 生成順序是 persona 與記憶實體 → session 模擬器記錄 add／update／delete 與狀態前後值 → 多代理生成對話 → grounding、coherence 與人工檢查 → 依軌跡出題。真值在對話生成之前就存在，因此不必由語句猜測哪個版本生效。

    §3.3、Appendix B 自動 grounding 檢查由三個模型各自判斷；論文寫的是三者一致才接受，否則回饋再生成。每個 persona 抽 5% 對話做人工作業；若發現軌跡與語句不符，整批退回。這與後續答題 criterion 的三裁判多數決是兩個不同程序。

    分層導讀

    先在帳本寫清楚『喜好改了、目標完成了』，再把帳本變成對話。這樣出題時知道目前哪一版才有效。帳本是合成資料的真值，不是真人記憶。

    流程是種子人物與記憶實體 → session 模擬器決定新增、更新、刪除或中性互動 → 記錄每個 session 前後的記憶狀態 → 多代理提示生成對話。記憶分為偏好、活動、目標；共有 10 個專業人物設定。先有可追蹤狀態再生成文字，才有辦法明確知道失效的內容。

    這種生成順序降低標註歧義，也造成重要的外推限制：使用者真實話語可能暗示、反諷、跨人稱或互相矛盾，模擬器的操作類型卻事先已知。評測的是在受控狀態演化下的記憶能力，不是現實部署的全部難題。

    自我檢測
    為什麼不能只由最終對話倒推答案？

    因為更新與刪除的有效時點可能模糊；明確狀態軌跡提供可檢查的 gold。

    分層導讀

    小樹原本喜歡海鮮，後來說『我現在不能吃蝦』。題目若問今天晚餐，舊喜好仍是歷史，卻不能直接當推薦理由。

    本站用三輪示例重建狀態：t₁ 新增喜好海鮮；t₂ 更新為避免蝦；t₃ 聊天但不改記憶。t₃ 查詢的有效集合保留更新後狀態，舊版本可作歷史證據，不能作現況推薦。Memora 的 session simulator 就是在生成對話前記錄每輪前後狀態，再以該軌跡產生題目與準則。

    把每筆記憶表示成 (實體, 值, 有效起點, 有效終點) 是本站的分析模型，不是論文宣稱的儲存格式。t₁ 的『喜歡蝦』在 t₂ 後終止有效；中性輪 t₃ 不應默認再次更新。若問『以前喜歡什麼』，仍需讀 t₁；若問『現在可推薦什麼』，需依 t₂。評分時 presence 檢查有效資訊、absence 檢查失效內容是否被錯用。

    自我檢測
    t₃ 的中性聊天是否讓 t₂ 的更新自動失效？

    否；沒有新狀態操作，t₂ 的有效版本仍在。

    三種任務與資料品質

    原文 §3.4–3.6、§4.2、附錄 C核對原文 PDF ↗

    原文方法與證據

    Figure 1、§3.5、§4.2 原文的回想題詢問待辦；推理題把兩筆雜貨支出與預算合算；推薦題須在偏好由某類電影轉移後給新建議。每題有 presence criteria（有效內容應出現）與 absence criteria（失效內容不應出現）。

    §4.2、Appendix C GPT-4.1、Claude Haiku 4.5 與 Gemini 2.5 Flash 對每個 criterion 給二元判定，採多數決。抽查的人類與裁判平均一致率 88.3%，人類標註者間 Cohen κ 為 0.86–0.90。這校驗判準可靠性，並非回答系統的任務成績。

    分層導讀

    同一段長期相處，可能問『我以前說過什麼』、『依我現在情況推論什麼』，或『現在推薦什麼』；三題需要的記憶不一樣。

    Remembering 回想已知資訊；Reasoning 跨記憶推理；Recommending 根據有效偏好建議。每題配有應出現的 presence criteria 與應排除的 absence criteria。作者用自動 grounding 檢查、人類評估及三個 LLM 裁判多數決；裁判與人類標註的平均一致率為 88.3%，人類間 Cohen κ 為 0.86–0.90。

    88.3% 表示所抽查 criterion 的標註一致，不保證所有題目在三種跨度或所有錯誤類別都同樣可靠。criterion 的顆粒度和題目生成方式會影響 FAMA；評閱開放式回答時，『合理改寫』是否等於滿足 criterion 也取決於裁判。

    自我檢測
    推薦題只要提到一個有效偏好就算完全正確嗎？

    不一定；分數由該題所有 presence 與 absence criteria 共同決定。

    兩道品質關卡：對話真值與答案裁判

    原文 §3.3、§4.2、Appendix B–C核對原文 PDF ↗

    原文方法與證據

    §3.3、Appendix B 合成對話的 grounding 檢查要求三模型對應的操作與實體一致；不合格者重生。每個 persona 抽 5% 對話做人工品質檢查。

    §4.2、Appendix C 答題準則由 GPT-4.1、Claude Haiku 4.5、Gemini 2.5 Flash 各給二元判定，再多數決。人機平均一致率 88.3%；人與人 Cohen κ=0.86–0.90。此統計不等於全部回答的正確率。

    分層導讀

    先查劇本有沒有把『更新』真的說出來，再查答題者有沒有沿用舊版本。這是兩個不同的檢查，不可把它們的投票規則混成一個。

    對話生成後，grounding 檢查要求三個模型一致，若不一致便回饋重生；每個 persona 再抽 5% 對話人工檢查。答題階段則對每個 presence／absence criterion 用 GPT-4.1、Claude Haiku 4.5、Gemini 2.5 Flash 各判 yes/no，以多數決定分。人類與裁判平均一致率 88.3%，人類間 κ=0.86–0.90。

    前一道關卡檢驗『合成對話是否忠於預設狀態』，後一道檢驗『開放式回答是否滿足二元準則』；兩種誤差來源不同。88.3% 是抽查標註的一致率，不是裁判在所有可能答案上的準確率，也不能推出每一任務、每一失效類型的分歧率相同。本站建議保存分歧與邊界案例做分層人工複核。

    自我檢測
    對話 grounding 的三模型一致與答案 criterion 的三模型多數決相同嗎？

    不同；前者要求一致並可能重生，後者採多數決計分。

    FAMA：把『不該用的舊資訊』扣回來

    原文 §4.2、未編號 FAMA 公式核對原文 PDF ↗

    原文方法與證據

    §4.2、未編號 FAMA 公式 對單題 \(q\)，令 \(P_q\) 為有效資訊 criteria 數，\(F_q\) 為排除失效資訊 criteria 數；通過數各為 \(p_q,f_q\)。原文的兩項準確率與權重可寫為：

    \[\mathrm{MPA}_q=\frac{p_q}{P_q},\qquad \mathrm{FAA}_q=\frac{f_q}{F_q}.\]
    \[\lambda_q=\frac{F_q}{P_q+F_q},\qquad \mathrm{FAMA}_q=\max\{0,\mathrm{MPA}_q-\lambda_q(1-\mathrm{FAA}_q)\}.\]

    本站手算 若 \(P_q=4,p_q=3,F_q=2,f_q=1\)，MPA=0.75、FAA=0.5、\(\lambda_q=1/3\)，所以 FAMA=\(3/4-(1/3)(1/2)=7/12\approx0.583\)。任務成績是同一任務、同一跨度內逐題平均後換為 0–100；不應先把三任務混成一個百分率。

    FAMA 手算工作台 本站依原文公式實作

    設定每題兩類 criterion 的通過數；下方即時計算 MPA、FAA、λ 與 FAMA。兩類至少各 1 項。

    分層導讀

    回答一題，不能只算寫對幾項，也要看有沒有把過期資訊寫進去。下方計算器用簡化的二元 criterion 實例重現原文公式。

    對每題，MPA 是應包含有效記憶的 criterion 通過比例；FAA 是應排除舊記憶的 criterion 通過比例。λ 是 absence criteria 在兩類 criterion 中所占比例。FAMA = max(0, MPA − λ(1 − FAA))，所以漏掉有效內容會少得分，錯用舊內容會再扣分。三個任務分開把逐題 FAMA 平均並換成 0–100。

    設 presence 通過 3/4、absence 通過 1/2，則 \(\lambda=2/(4+2)=1/3\)，\(\mathrm{FAMA}=\max(0,3/4-(1/3)(1-1/2))=7/12\approx0.583\)。\(\lambda\) 隨每題 criterion 數量而變，不是論文固定調好的超參數。當題目完全沒有其中一類 criterion 時，須先檢查資料規則；本文給出的公式未單獨討論零分母處理，本站互動示範要求兩類各至少一項。

    自我檢測
    只要 FAA=1，FAMA 就一定是 1 嗎？

    不一定；此時扣分為零，但分數仍等於 MPA，可能小於 1。

    從單題到 Table 4：分數的分母

    原文 §4.2、Table 3–4；本站推導核對原文 PDF ↗

    原文方法與證據

    §4.2、Table 3–4 原文先將固定任務／跨度中的逐題 FAMA 加總並正規化到 0–100，再把同一任務的三個跨度分數相加，得到 Table 4 的 0–300。

    \[S_{k,d}=100\frac{1}{n_{k,d}}\sum_{q\in(k,d)}\mathrm{FAMA}(q),\qquad A_k=S_{k,\mathrm{week}}+S_{k,\mathrm{month}}+S_{k,\mathrm{quarter}}.\]

    本站推導 \(k\) 為任務、\(d\) 為跨度、\(n_{k,d}\) 為該組題數。Table 4 的 \(A_k\) 等權相加三個跨度；不要誤讀為全部題目的單一準確率。

    分層導讀

    一題的分數先算出來，同一種任務再平均；表格最後把三個時間跨度加起來。每次加總後，滿分代表的東西都變了。

    FAMA(q) 在 0 到 1。對固定任務與跨度，Table 3 分數等於該組所有題目的 FAMA 平均乘 100。Table 4 則把該任務的週、月、季三個 Table 3 分數相加，上限 300。由於三組問題數是 150、150、300，Table 4 的等權跨度加總與把全部題目攤在一起求平均不等價。

    設週、月、季分數為 W,M,Q，Table 4 指標為 W+M+Q。若要以全部題目加權，應是 (150W+150M+300Q)/600，這是本站推導的另一指標，原文 Table 4 沒有報它。舉例 W=80,M=60,Q=40：原表合計 180/300，題數加權平均則為 55/100。比較時須先說明統計單位。

    自我檢測
    Table 4 的 180 分是否等同全部 600 題平均 60%？

    不一定；Table 4 等權加總三種跨度，季度題數是其他跨度的兩倍。

    錯誤分析：三任務失敗的機制不同

    原文 §6、75 個人工抽查錯誤核對原文 PDF ↗

    原文方法與證據

    §6 作者從三種任務各抽 25 個錯誤案例，共 75 個，針對每項任務表現最佳的記憶代理分類。推薦錯誤中 16/25 涉及未忘掉舊記憶、7/25 只取回部分偏好；回想 18/25 為部分取回；推理 25/25 都涉及相關記憶取回不全。

    統計讀法 這些比例的條件是「已出錯且被抽中」，所以 16/25 不等於全部推薦題的 64% 都錯用舊記憶。分類可提示機制，卻未把檢索失敗與狀態更新失敗做互斥的因果分離。

    分層導讀

    推薦錯不一定是『不會推薦』，有時是沿用舊喜好；推理錯也未必是算術差，可能少了關鍵資料。

    作者從各跨度的錯誤中抽 75 例，每任務 25 例，分析該任務表現最好的長期記憶代理。推薦 25 錯中，16 例（64%）和未忘舊記憶有關、7 例（28%）是偏好只取回一部分；回想 18/25（72%）是部分取回；推理的 25 個錯誤全部涉及相關記憶取回不全。這些是條件於『已出錯』的人工分類比例，不是整個評測集的錯誤率，也不是每個代理都相同。

    推薦容許近似偏好，所以在 Table 3 相對較穩；需要合併多筆的推理只要缺一項便可能失敗。作者把錯誤樣本的共同現象指向 partial retrieval 與 outdated memory。本站補充：若要比較兩個根因的因果貢獻，可對同一問題分別提供 oracle 有效記憶、oracle 更新決策，做 2×2 消融；論文的錯誤分析尚未做這個干預。

    自我檢測
    『25/25 推理錯誤有部分取回』可推論所有推理題都失敗嗎？

    不能；分母是被抽中的錯誤案例，不是全部推理題。

    A　方法重建：輸入、狀態、步驟與公式

    原文 §3–4 輸入與真值。先選十種專業 persona 和三類記憶實體（偏好、活動、目標），再由 session simulator 產生 add、update、delete 或 memory-neutral 操作。每個 session 都有前後狀態快照；這條軌跡是題目所用有效版本的來源。多代理對話生成器把指定操作說成自然語言，grounding 檢查不容未追蹤資訊混入。最後按軌跡出 Remembering、Reasoning、Recommending 題，標明應出現的有效資訊與應避開的失效資訊。

    原文 §4.1–4.2 被測系統與評分。直接模型按 context window 可容納的歷史作答；六個記憶代理增量攝入、查詢時檢索，並共用 GPT-4o-mini 回答。每題的 presence、absence criterion 由三裁判逐項二元判定，取多數決。令有效 criterion 數為 \(P\)、通過數為 \(p\)，失效 criterion 數為 \(F\)、成功排除數為 \(f\)：

    \[\mathrm{FAMA}(q)=\max\left(0,\frac pP-\frac F{P+F}\left(1-\frac fF\right)\right).\]

    本站重建 若 \(P,F>0\)，未截零時可整理成 \(p/P-(F-f)/(P+F)\)：每個失效 criterion 違反都扣 \(1/(P+F)\)，但每個有效 criterion 命中增加 \(1/P\)。此式用來檢查分母與實作；原文沒有單獨規定 \(P=0\) 或 \(F=0\) 時的除零政策，重現評估需讀公開資料與程式處理方式，不可任意外推。

    原文 Table 3–4 同一任務、同一跨度先對逐題 FAMA 取平均並乘 100；跨三跨度相加才是 Table 4。答題可見歷史、逐題準則、裁判、任務彙總是不同階段；重算表格時每階段都需固定版本。

    D　可否證的後續研究假說

    本站提出的可否證假說，非原文結論 H₁：在固定 persona、session 數、總 token、題目模板與回答骨幹後，只增加相關 update/delete 密度，FAMA 與 FAA 仍下降。反證條件是多個種子與相同裁判下，受控高低 mutation 組的平均差接近零。H₂：在固定 mutation 數時，只拉長無關中性歷史，MPA 的下降大於 FAA 的下降；若兩者不變，則原有跨度趨勢可能主要來自狀態變動或題目組成。這兩個假說共同建立 2×2 的長度 × mutation 設計。

    最小實驗。同一組狀態軌跡生成四個配對版本：短／長歷史與低／高 mutation。保持最終有效狀態、查詢和 presence criteria 不變；要改 mutation 時需插入可核對的中間版本，並重新定義其 absence criteria。用同一回答模型和相同 token 預算測外部記憶方法，逐題報 MPA、FAA、FAMA 與檢索命中；由 persona 聚類估區間。若只看 FAMA 總分，就無法辨識「想不起有效資訊」與「錯用舊資訊」。

    失敗分類的干預。對同一錯題做兩個 oracle：只給正確檢索集合、只給正確有效版本判定，再組合兩者。四格結果可測「找不到」與「找到了但未判失效」的交互作用；這是本站設計，Memora 原文沒有執行。若 oracle 檢索仍錯，應檢查推理或 criterion 裁判，而非繼續把原因全歸給記憶。所有新實驗都應報成本與生成品質，避免把更難的合成文字誤判為純記憶壓力。
